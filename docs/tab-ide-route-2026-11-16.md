# Tab в официальном IDE: маршрут и граница текущего патча

Дата: 2026-11-16.

## Результат

Для исследованной установленной сборки найден локальный путь официального IDE:
`LanguageServerService/HandleStreamingCommand`, а не чатовый `StartCascade`.
При воспроизведении его полей через тот же native backend 2.32.1 обычный Tab
по-прежнему выбирает `tab_flash_lite_preview` и не получает доступного AICode
experience. Исключение принудительного `requestedModelId` проблему не устраняет.

Сравнение исходного и пропатченного конвертеров подтвердило различие их запросов,
но **оба варианта получили 404**. Недостаточно просто вернуть исходный конвертер
или убрать локальный запрет Tab. Рабочая серверная привязка Tab не установлена.

Краткие сетевые доказательства и хеши:
[evidence/tab-ide-route-2026-11-16.json](evidence/tab-ide-route-2026-11-16.json).

Возможная зависимость доступности Tab от подписки остаётся непроверенной
гипотезой. Сравнения с аккаунтом с действующей подпиской не было; текущие
результаты эту зависимость не подтверждают и не исключают. Проверка тарифного
условия отложена до появления возможности такого сравнения.

## Как обращается IDE

В установленном `extensions/agy/dist/extension.js` класс
`AntigravityServerClient` использует Connect transport и существующий локальный
CSRF token. Локальный base URL поступает из конфигурации server URL либо порта
backend. Вызов — `handleStreamingCommand` сервиса
`exa.language_server_pb.LanguageServerService`.

| Параметр | Дополнение | Следующая правка / переход |
| --- | --- | --- |
| requestSource | SUPERCOMPLETE | TAB_JUMP |
| diffType | TMP_SUPERCOMPLETE | TMP_TAB_JUMP |
| supercompleteTriggerCondition | TYPING | AUTOCOMPLETE_ACCEPT |
| ignoreSupercompleteDebounce | true | true |
| requestedModelId | Не задаётся frontend builder | Не задаётся frontend builder |

Передаются документ, URI workspace, язык, позиция курсора, окончания строк,
признак несохранённых изменений и настройки отступов. Отмена поступает через
AbortSignal. Для дополнения IDE использует character diff, для перехода —
jumpPosition, а не обычный чатовый текст.

В native найдены `CompletionProvider.HandleTab`, `updateTabRequest`,
`getCompletionsForTab` и общий CodeAssist generation client. Для personal-consumer
ветки выбор облачной генерации зависит, в частности, от USE_AICODE. Native
способен направить её в AICode либо в прежний CCPA. Признаков отдельного Tab URL
в проверенном frontend builder не найдено.

## Что проверено вживую

Использовался синтетический Python-документ с `def add(a, b)` и незавершённым
`return`. Реальные проекты, открытые документы пользователя и OAuth не менялись.

1. В диагностической копии полей IDE убраны requestedModelId и отличия размера
   отступа. Через текущий launcher вернулся локальный FAILED_PRECONDITION 400:
   Tab experience не опубликован в fetchConfig. Генерация до облака не дошла.
   Значит, этот конкретный локальный отказ нельзя называть upstream 404.
2. Для сравнения native конвертеров использован отдельный relay с фиксированными
   официальными HTTPS hosts, сохраняющий исходную авторизацию и тело запроса.
   Он не подменяет модели, лицензии или ответы сервера.

| Вариант | Фактический облачный вызов | Выбранный experience | Результат |
| --- | --- | --- | --- |
| Native с текущим исправлением конвертера, без отсекающего адаптера | POST `https://aicode.googleapis.com/v1alpha:streamGenerateContent` | tab_flash_lite_preview | 404 NOT_FOUND |
| Резервная сборка с исходным конвертером | Тот же AICode URL | chat-gemini-3.1-pro-low | 404 NOT_FOUND |
| Прежняя CCPA-ветка | POST `https://daily-cloudcode-pa.googleapis.com/v1internal:streamGenerateContent` | Не подтверждался парсером relay | 403 PERMISSION_DENIED, #3501 |

AICode `fetchLicenses` и `fetchConfig` дали 200. Свежий список availableExperiences
не содержит Tab. Поля верхнего уровня обоих AICode prediction-запросов одинаковы:
`aicode`, `contents`, `entitlement`, `generationConfig`, `sessionId`,
`systemInstruction`. У aicode в обоих случаях одно поле — experience.
Это сравнение структуры, а не утверждение о побайтовом равенстве contents.

Ошибка AICode: `Requested entity was not found.` Она подтверждает отказ выбора
ресурса для данного запроса и аккаунта, но не доказывает глобальное удаление
модели, конкретное тарифное условие или отсутствие ресурса у всех пользователей.

## Чего не хватает для исправления

Текущее исправление переносит исходное выбранное имя в `aicode.experience`
и корректно работает для опубликованных experiences. Но внутренний ID
`tab_flash_lite_preview` не является подтверждённым доступным experience этого
аккаунта. Для настоящего Tab нужна проверенная серверная привязка модели/продукта
или доказанный другой маршрут. Произвольное имя endpoint, подделка entitlement
или снятие локального отказа такую привязку не создают.

Копирование исходного конвертера возвращает другое, тоже отсутствующее имя.
Подстановка опубликованной Flash Lite могла бы выполнять задачу дополнения,
но это был бы отдельный режим на другой модели, не доказательство доступа
к исходным Tab-моделям. Такой подмены не сделано.

## Границы проверки

- Исследован установленный код IDE и воспроизведён его специализированный RPC
  на том же native build. Сетевой захват действия клавиатурой в окне IDE не проводился.
- Текущий тест сравнения конвертеров относится к SUPERCOMPLETE. Предыдущий
  прямой Tab Jump вызов также возвращал 404, но не объявляется повторно проверенным
  этим сравнением.
- Наличие внутренних карточек M19/M28 и remainingFraction=1 не подтверждает
  публикацию или успешную генерацию этих моделей на сервере.
- В диагностическом Python-процессе временно разрешён replay bootstrap 2.32.1;
  production guard SDK не изменён. Нулевой bootstrap не считался ответом модели.
- Runtime, установленные приложения и production-код патча не изменялись.
  Рабочее исправление Tab и успешный ответ исходной Tab-модели пока не получены.

Локальные повторяемые скрипты и расширенные результаты находятся в исключённой
из Git папке `test_cache/tab-ide-2026-11-16/`. Relay сохраняет только маршрут,
имя модели/experience, имена полей и безопасный серверный статус — без OAuth,
содержимого документов и запросов. Сравнение binary backup означает исходный
конвертер, а не гарантию полной pristine-сборки: хеш backup приведён отдельно.
